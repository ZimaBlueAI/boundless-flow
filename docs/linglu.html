配置灵录

在引导／高级设置的「灵录 API」区域选择服务，填写实际可用模型、地址和鉴权。Ollama 可使用本地服务，不要将不存在的示例模型名作为已安装模型。灵录的配置与普通翻译配置分别检查。

可按会议需求调整场景、温度、输出长度和触发频率。请求频繁会增加服务调用；先短录音测试主题树和报告，再用于长会议。

录音、复核与导出

  1. 录音中：在会议区域展开实时分叉树，观察主题与段落联系。
  2. 录音结束：检查已保存会话、主题、摘要、决策与行动项，结合原文修订。
  3. 交付：选择主题，先预览再导出报告；检查实际导出路径。

场景与报告主题

可选择通用、个人录音、双方对话、私人聚会、工作会议、公开会议、商业会议和学术研讨场景，以及自动场景选择。若自动选择不合适，明确选择场景，个人录音无需强行提炼商业 KPI。

可选择 terminal-grade、keynote-stage、editorial、minimal-print、sumi-ink 五种报告主题。主题改变报告呈现，不应改变会议事实。预览通过后使用导出入口交付。

报告与会议数据

灵录主题树、会议原文和纪要是不同数据，需确认本次会话和输出范围。云端分析会发送所需文本到你选择的服务；使用本地服务时也应确认服务地址确实在本机。

本地缓存与后台分片转写

启用灵录，并使用本地 SenseVoice 或 FunASR 转录时，音频按约 30 秒保存为 WAV 分片，后台逐片转写。实时字幕继续使用原有识别链路，灵录使用分片转写原文整理纪要。云端实时转录仍走原有路径，不使用这一套本地分片流程。

  1. 在「配置引导页」的灵录区域展开「音频缓存位置」。留空使用默认会话存储位置，或选择空间充足磁盘上的绝对目录。完成引导并保存；修改仅对新录音生效。
  2. 开始录音后，灵录面板显示待转写、转写中、已转写、待重试数量。「已转写」不等于纪要已经完成，还需检查整理结果。
  3. 点击「停止」后，任何非空短尾段都会继续处理，不必凑满 30 秒。保持软件运行，等待转写、整理和保存完成。
  4. 若转写失败，先查看错误并解决问题，再点「重试处理」。失败分段的缓存录音保留；纪要请求失败有独立的重试状态。

处理积压过多或磁盘空间不足时，会停止继续采集，保留已接收的音频继续处理。请查看停止原因，再决定是否重新录音。处理中不要移动缓存目录，也不要关机。

原始录音、分片转写原文和纪要都保存并核验后，已完成的临时分片可归入缓存旁的「可删除」文件夹。这只是归档，不执行删除，也不会释放磁盘空间。未完成或失败的分片留在工作缓存中；手动清理前请核对已保存会话结果，正式录音和纪要会保留。

灵录没处理完，可以关窗口吗？

可以只关界面，让软件继续处理。关闭主窗口时，若灵录仍在录音、整理或保存，会出现任务提示。实时会议纪要、AI 纪要与芽记报告也纳入退出等待。

  1. 继续使用：点击「取消」，留在当前页面。
  2. 后台处理：选择「仅关闭界面 · 后台继续」。主窗口隐藏，软件仍在托盘运行；未停止的录音也会继续。若不想再录音，先点击「停止」。
  3. 退出软件：选择「保存并退出」。软件先停止录音，收尾最后一段，再等待灵录处理与保存。任务未完成时会暂缓退出，可先后台处理，稍后再退出。
  4. 查看结果：点击托盘图标或托盘菜单「打开」，返回软件核对会话与报告。

后台运行需要电脑保持开机；关机或在任务管理器中强制结束进程会中断处理。窗口隐藏不等于软件已经退出。保存失败时，请检查提示和已保存录音。若提示「灵录整理已暂停」，说明纪要请求已连续失败 3 次；先查看服务错误，服务恢复后点击「重试整理」。隐藏界面只保留当前运行软件中的任务，不会启动另一套处理进程，也不能代替关机前保存。

纪要结果没有完整返回时

此响应检查需 Windows r512 或后续安装预览。

当服务达到输出上限、拒绝结果、返回工具调用，或未提供完成标记时，不会把这次结果当作已完成纪要。原始转写、上一份结果和待处理批次保留在当前运行的软件中；JSON 看起来合法也不等于已经完整生成。

  1. 先查看服务提示。转写已完成时，纪要仍可能暂停，两者分开处理。
  2. 在配置引导页核对已保存的灵录服务和模型。选择能完整处理本次内容的模型，或修正服务配置，使其返回完成信息。
  3. 在进度卡中点击重试失败任务。重试绑定本次录音，沿用原待处理文字，无需重录；仅保存配置不会自动重放任务。
  4. 处理和保存完成前，保持软件运行及电脑开机。可隐藏界面保留待处理内容；不支持关机后自动接续。

已明确不完整的结果会暂停，等待你决定，不反复请求同一内容。临时网络故障仍按原有次数和间隔有限重试。完成标记不能证明没有遗漏事实，仍需结合引用和原音复核。

看懂本次录音的后台进度

此状态卡需 Windows r512 或后续安装预览。适用于启用灵录的本地分段转写，云端实时识别沿用其对应状态。

  1. 在主工作区查看状态卡。卡片位于录音控制区下方；灵录嵌入视图和独立窗口也显示同一类状态。录音停止后，转写和纪要仍可能继续。
  2. 先看已封存时长与四项数量。「待转写」「转写中」「已转写」「需重试」分别计数。「已封存」指已经完成分段落盘确认的缓存音频，不代表整场原始录音或报告已经保存完成。
  3. 展开「音频与纪要详情」。核对进入分段写入流程的音频与已封存音频。未封存部分不能当作已落盘；非空短尾段会在停录后封存处理。文字校正、转写和纪要分别收尾，不合计成完成百分比。
  4. 有异常时按提示处理。积压、磁盘空间不足、磁盘检查失败和保存未确认会分别说明。32 片是未处理音频触发保护停止的阈值；停止后还要排空已接纳音频，数量可能略超，不是剩余时间或总容量。
  5. 只重试当前失败任务。后台确认可重试时才显示按钮，操作绑定本次录音。若状态读取失败，旧读数会明确标记；先点击「刷新状态」。模型线程已结束或音频未确认保存时，核对原音、修正配置，再按需自行导入录音。

处理中或失败的缓存不会因点击刷新、重试或关闭报告而清空。状态卡消失不等于所有文件均已保存成功；请在会话浏览中核对原音和文字。关闭主界面时，仍按下方的未完成任务提示选择后台继续或等待保存。后台处理需要电脑保持开机。
