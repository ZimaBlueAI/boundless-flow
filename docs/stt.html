开始与停止

  1. 在录音设置确认输入设备，选择已登记的识别模型和源语言。首次加载模型可能较慢，先等待状态反馈。
  2. 点击「开始」或按已配置快捷键。短句测试后检查临时结果与最终原文。临时文字可能继续修订；复核和生成纪要时，使用段落确认后的原文。
  3. 点击「停止」后等待收尾完成，再在会议视图查看记录。不要把仍在处理中当作已保存完毕。

停止录音：等收尾完成，再确认记录

本节停止保护需 Windows r514 或更新版本。请以实际安装版本为准。

  1. 开始前核对输入设备和识别语言，先说一句短句，确认收到声音。录音中需要换输入框时，先确认新位置；指定声音自动输入仍未开放，见指定声音试认的适用范围。
  2. 结束时点击一次停止，等待保存与处理完成。正常停止时，末尾已接收、已转换的声音即使不足常规分段长度，也会继续收尾；不要因为暂时没有新字幕就反复点击开始。
  3. 若出现收尾失败、设备故障或音频积压提示，先回主窗口检查状态，再到会话浏览查看已保存的录音。未确认完成的录音不能当作完整成功；先听原音、确认保留范围，再明确重试或导入已保存音频转写。不要将缺失前后的声音当作一段连续录音，也不要反复点击开始。
  4. 使用云端识别时，分别核对本地录音已保存和云端识别已完成。前者不表示服务已返回最后一句文字；过短的结尾可能没有云端字幕。需要补查时，先听已保存音频，再决定是否重新转写。

没有确认停止、保存或处理完成时，继续查看当前任务的提示。遇到错误先检查已保存内容，避免重复录音或漏掉最后一句。

识别语言、译文语言与界面语言

适用版本：Windows r512 或后续安装预览。更早安装预览不含本节的源语言绑定修复。先按下面的三项分别核对，再用短句试录。

设置决定什么中文讲话、英文字幕的例子
识别语言 / 源语言告诉识别与翻译流程，你准备讲什么语言。确定讲中文时选中文。
翻译目标语言决定译文使用什么语言。选英语。
界面语言改变菜单、按钮和提示文字。中文或 English 都可以，不替代识别语言和翻译目标。
  1. 在录音设置先选识别模型，再核对源语言。SenseVoice 选择自动时，按模型真实的自动识别处理，不再把“自动”当成“中文”。确定主要讲中文时，可以明确选中文；换语言或任务后重新核对。
  2. 需要译文时，再选翻译目标语言。例如中文讲话译成英文，分别设置“中文 → 英语”，然后试录一句，先看原文，再看译文。
  3. 想查看将要发送的翻译请求，可在主录音的翻译设置展开术语与翻译背景，填一句样文，点检查术语与请求（不调用模型）。检查绑定该页当前的识别语言、识别引擎和主翻译目标；样文仍是原文内容，不用把语言名称填进样文。
  4. 切换源语言、识别引擎、主翻译目标或翻译模型后，重新检查请求；旧预览会清除，旧检查的晚到结果不会覆盖新选择。这个检查不识别音频，也不运行翻译模型；实际效果请用短句试录核对。

开启前文背景是另一个可选设置：默认 0 不带前文，保存启用后才会使用。分段与已保存音频翻译如何保留本任务内的原文背景，见同传语言与前文背景。使用同传时，还要在工作台核对本次任务的源语言和目标语言。

识别后端与模型文件

在配置引导的「本地模型库」将用途设为「语音识别」，再选择模型家族。登记 SenseVoice ONNX 文件夹、完整 Fun-ASR-Nano-2512 文件夹，或 whisper.cpp GGML 的 ggml-*.bin 单文件。不同大小或量化版本分别命名、登记，使用页从模型库选择。FunASR Nano 的根 model.pt 包含语音与语言模型权重，仍须保留 Qwen3-0.6B 配套配置和分词器；原始 Whisper safetensors、PyTorch 或 GGUF 不能直接替代 GGML。SenseVoice 与 FunASR Nano 按录音片段识别；Whisper 以文件转写为主，不能据此承诺原生流式或低延时。

登记后，在库上方「转录使用的模型」选择名称，点击「检查模型」，再展开「试转录一段录音」。需要下载时，点击当前家族旁的「下载准备」，或展开库后方的「下载模型与组件」；先核对来源和目标磁盘，再明确开始下载。登记只加入当前草稿，最后请完成并保存配置。

识别后端需要对应的运行组件和模型文件。若提示缺少组件，先按提示补齐，再重新检查模型。选择下拉菜单中的后端不会自动安装组件。

讯飞实时识别：配置一次，录音时选择

本节讯飞连接步骤需 Windows r512 或后续安装预览。截图为实际编译界面的示例配置，不表示已完成真实账户识别质量测试。

  1. 先在讯飞控制台为当前应用开通实时语音转写大模型，再打开软件的配置引导 → API → 讯飞 iFLYTEK，启用这张卡片。
  2. 地址填写 wss://office-api-ast-dx.iflyaisol.com/ast/communicate/v1。按 App ID → API Key → API Secret 的顺序，填写该产品控制台提供的信息；再按名称选择识别模式，完成并保存配置。两个密钥分别填写。
  3. 重新打开卡片检查保存状态。App ID 仍可见；两个密钥框均留空并显示已配置 · 留空保留，表示继续使用已保存值。确实要移除时，再点击对应字段的「清除密钥」。

在录音设置选择实时 API → 讯飞 · 实时语音转写大模型。这里按名称显示已保存的模式，只能查看。三项认证信息只在配置引导保存，录音页不用重复填写；需要修改时点击管理服务。

经典 RTASR/IAT 地址和旧模型值会作为「旧配置」保留，不会自动改成新协议。迁移时先确认同一应用的产品权限，再主动修改地址、选择新模式并保存。

点击「开始」后，麦克风音频会持续发送到讯飞，服务可能计费。源语言不符合所选模式时，会在开始前提示并阻止录音。点击「停止」后，剩余音频仍会提交，并等待服务端确认最终结果；收尾中请等待，不要立即开始下一次。断线或处理失败会显示错误，不会自动重连或重发；已确认文字仍保存，临时文字不会被当作最终结果。正常存储时，会议会话会保留原音供重转写，不依赖另存 WAV 的选项。出现存储提示时先检查磁盘空间；存储失败时不能保证原音完整保留。

实际结果受账户权限、网络、音频和语言影响。先做短录音测试，复核人名与数字；不承诺固定准确率或延时。查看讯飞官方协议、权限与语言列表 →

字幕显示与文件转写

多语言字幕按段对齐。字号只改变当前页面阅读，不暂停后台翻译；「专注阅读」提供更清晰的阅读区域。浏览历史时暂停跟随，回到最新内容后继续观察新段落。可见段数限制只影响显示，完整译文在翻译恢复与会议导出中查找。

开启翻译后，完整句可先显示译文；尚未说完的价格、数字或条件可能暂缓，等待后续内容补齐，兼顾原意完整和字幕更新。录音片段结束时，会继续处理保留的末尾内容。短句暂时没有译文时，先看原文是否已出现、录音是否仍在继续，再等待后续讲话或片段收尾。

本地 Fun-ASR-Nano 转写长文件时，录音按最长 16 秒的非重叠片段依次处理，不足 16 秒的末段也会处理。各片段独立保留文字，重复发言仍需对照录音复核。查看分段进度，取消后等待任务结束。模型未正常结束生成时会报错；取消或失败不算全文转写成功，保留原录音，检查提示后再重试。

点击「音频转写」选择文件。使用与当前文件匹配的识别后端和语言，完成后复核人名、数字、专有名词与发言人边界。原生离线转写需要随程序配套的 native-stt 组件。

悬浮转录

顶部「悬浮转录」打开轻量控制与字幕窗口。录音使用同一应用的输入与快捷键设置；先确认主界面可正常启停，再验证悬浮状态。悬浮窗口中的实时显示不代表独立启动了另一套识别模型。

悬浮控制窗提供开始、停止和返回主窗口按钮。说话时可查看声波反馈，在字幕窗阅读原文和译文；录音状态以控制窗和主界面的提示为准。

本地文字整理试用

本地文字试用已包含在 r492 Windows 安装预览中。增强语音输入的实时投递仍未开放；这里可以试用本地文字规则，不会向其他应用自动输入。

打开录音设置 → 输出方式 → 文字整理，先用一句容易核对的话试试。本地预览不需要配置文字模型。要整理原始文本或已保存的转写片段，使用下方的文字整理工作区。

模式本地试用会做什么
原文保持输入原样，不应用词典、禁改规则或格式模板，已保存的规则仍保留。
上下文校正按适用的词典精确替换，保守保留不确定内容。输出用途只限定词典范围，不套用排版；本地试用不请求模型。
智能整理 · 本地改口与格式本地处理支持的明确改口和词典规则。聊天、邮件、清单只整理已有文字的格式，不编造缺失信息。

先试一句话

  1. 将「文字整理」选为智能整理 · 本地改口与格式，「输出用途」选为普通文字。
  2. 展开个人词典与禁改词。添加 齐码蓝 → ZimaBlueAI，用途选所有用途；再添加 无界音流 → Boundless Flow，用途选邮件。「听到」必须与原文精确一致；第二条只在输出用途为邮件时生效。
  3. 可在「禁改词」中单独写一行 一号项目，然后点击应用文字规则。如果提示重叠或冲突，先修正规则再继续。
  4. 展开本地文字试用 · 原文与整理对照，输入 预算三千不对三万，齐码蓝负责一号项目。，点击预览本地整理。
  5. 逐字对照原文与预览。在这个支持的明确改口示例中，三千不对三万 整理为 三万，第一条词典将名字写为 ZimaBlueAI。再看下方修改理由；若出现保护或不确定提示，请核对保留的文字，不要强行改写。
  6. 确认后，再点击复制预览文字，自行粘贴到需要的位置。预览不会向光标输入，也不会自动保存这段试用文字。

设置规则时保住原意

最多保留64 条词典规则和32 条禁改词，每项 1 至 80 个字符。「听到」有重叠时，请合并规则或分到互不重叠的用途。禁改词不能同时与要求替换的「听到」重叠。配置有错时会保留待修复内容，不会悄悄覆盖为默认值；修正后应用规则，再按主界面的配置保存流程保存。

不知道 等不确定表达、引语和条件句，不会被当作确定的改口强行整理。关键数值与否定关系需对照原文，尤其是「不要」「不需要」等会改变句意的表达。

代码用途保护标识符，不调用复核模型。智能模式的模板只排版已有内容。切换模式会保留规则草稿；语音任务运行时，设置与预览控件会锁定，请等任务结束后再改。

模型复核是单独的可选项

智能模式可勾选智能模式使用文字模型保守复核（可选），为投递流程沿用已配置的文字模型。复核超过 1 秒或失败时，投递流程保留本地整理结果；若配置的是外部服务，该服务会收到确认文本。当前实时投递仍未开放；即使勾选此项，本地试用也始终不调用模型。任何模式的代码用途均不联网复核。

核对整理结果时，把日期、金额和人名与否定词一起看。例如“今天不付款，明天付款”不能变成“今天付款，明天不付款”。发现意思变化时，使用原文或已核对的本地整理稿。模型复核不能保证语义完全不变；当前增强实时投递仍未开放，本地试用不会调用模型。

本地预览只在点击后执行，不读取屏幕或剪贴板，也不自动保存试用文字。只有点击复制预览文字才写入剪贴板。这里的设置和示例不能代表实时自动输入已经交付，也不能据此判断优于其他产品。

把转写副本整理成可用文字

文字整理工作区已包含在 r492 Windows 安装预览中。它沿用已应用的个人词典与禁改词，不需要另外配置模型或 API。

从正在看的文字开始

  1. 在原始文本点击整理文字，将当前文字带入工作区。只想处理其中一段时，先在文本框选中这一段，再点击按钮。
  2. 也可在会话浏览 → 逐字稿预览，找到一段转写，点击该段的整理文字。选区优先；没有选区就使用整段。短句默认紧凑显示，长内容可在框内滚动，也可拖动文本框右下角调高。
  3. 在文字整理工作区核对来文名称和左侧原文副本 · 可编辑。可在副本中补字或删字；原始转写与录音保持原样。
  4. 确认本次模式和本次用途，再点击工作区里的整理文字。带入副本不会自动开始处理。
  5. 对照右侧整理稿 · 待人工核对，展开逐项差异查看改前、改后和理由。重点核对人名、数字、否定词与代码。
  6. 满意后点击复制整理稿，自行粘贴到需要的位置。结果不会自动覆盖会话、写入其他应用或保存为报告。

本次选项不会改掉中央设置

本次模式适合怎样使用
保留原文逐字保留当前副本，不应用词典、改口或格式。中央设置为原文时，这里也保持原文，不会自动开启整理。
保守规则应用适用的本地词典精确替换。用途只限定词典范围，不套用格式，也不请求文字模型。
改口与格式处理支持的明确改口、适用词典及所选用途格式，不补写缺失事实。并非通用语义纠错或自动润色。

本次用途可选普通文字、聊天、邮件、清单、代码。模式与用途只作用于当前副本；个人词典和禁改词仍在同一处维护，点击管理中央文字规则即可返回设置。先按上面的规则配置步骤应用有效规则，再回工作区整理。

改错了，或想换一段怎么办

  • 撤销整理把整理稿恢复成当前原文副本，并清除差异；不会撤销你对副本的手动编辑，也不会修改原始转写。清除整理稿只清除本次结果与差异。
  • 工作区已有副本时，从别处再次带入文字会先提示选择。点用新文字替换本工作区副本才替换；点继续当前副本保留当前工作。
  • 修改副本、本次选项或中央规则后，旧整理结果会作废，需重新点击整理文字。配置无效时请先修复，不会自动退回原文模式继续处理。
  • 收起或关闭工作区会保留当前运行中的副本，之前任务的迟到结果不会覆盖它。整理稿没有自动存盘；退出软件前，请先复制需要保留的文字。

每次最多处理65,536 个 Unicode 字符，emoji 按一个字符计数。超出范围时整段不处理，也不截断文字；可返回来源选取较小范围。差异较多时分组翻页。遇到忙碌、超时或容量提示，副本仍保留，请按提示调整后重试。

这条路径只使用本机文字规则，云端 API 调用和 API 费用均为零，不上传文字，也不调用中央设置中的文字复核模型。检查原音、确认事实和决定是否采用修改，仍由你完成。

看懂悬浮转录的开始、音量与停止状态

以下悬浮状态改进已包含在 r492 Windows 安装预览中。本节对应顶部悬浮转录打开的普通转录 Mini；增强语音输入的自动投递仍未开放。

  1. 打开悬浮转录，点击麦克风开始。先看状态文字，再判断是否正在录音；连点按钮或快捷键不会排队启动多次。
  2. 讲话时查看音量变化和字幕。音量来自实际收到的音频帧，不使用模拟跳动。静音帧的音量可以为零。
  3. 准备期间可点击取消准备，只取消本次准备。录音或文件转写期间点击停止转录后，请等待状态变化；文件转写的停止入口仍可使用。
  4. 点击返回主窗口只切换界面，当前后台任务继续。需要结束任务时仍须点击停止，并等收尾完成。
状态文字怎样判断与操作
准备中 · 尚未录音模型或设备仍在准备，尚未开始采集。需要中止时使用「取消准备」。
录音中 · 等待音频已收到录音开始状态，尚未收到本次音频帧。单凭这条提示不能判定麦克风损坏；可返回主窗口核对输入和运行提醒。
录音中 · 已收到音频已收到本次实际音频帧，包含音量为零的静音帧。不等于已识别出文字。
已请求停止 / 正在收尾保存停止请求已提交，或正在结束处理与保存，均不表示已经完成。等后台确认空闲后，再开始下一次。
状态待核对 / 请核对查看状态提示，必要时返回主窗口。停止失败会保留当前任务状态，可按提示再次点击停止，不会显示成已停止。

开始或停止超过 12 秒仍未确认时，会出现重新核对录音状态按钮。先点击核对，再按最新状态处理；软件不会自动重新启动。即使核对到空闲，之前的操作请求尚未返回时，开始仍保持禁用，避免重复录音。核对失败可再次核对；错误提示使用固定说明，不直接显示服务返回的敏感细节。

没有文字时

检查输入设备是否有讲话、麦克风权限、模型检查提示和录音状态。若使用云端识别，再检查账户权限与独立 ASR 配置。辅助发言人分析失败时可继续检查字幕结果，勿把所有故障都归为转录失败。

转写过程中改字，保留当前稿

从 r496 开始，文件转写仍在进行时，您对「原始文本」的手动修改会保留。后续识别结果单独放在「比较识别稿」里；声音面板选择原始文本时也共用这份保护。

  1. 看到「已保留您的编辑」后，展开「比较识别稿」。上方仍是您正在编辑的当前稿，下方是只读识别稿；长文可以滚动，也可拖高。
  2. 选「继续当前稿」会收起比较，不会替换文字；后续识别稿仍可再展开查看。
  3. 确实需要替换时，点「采用识别稿」。采用后可用「撤销采用」恢复此前的稿；若您又继续修改，撤销按钮会停用，避免丢掉新的修改。此前文字仍能从「查看采用前稿」中复制。
  4. 要永久保留当前稿，请使用原始文本的复制或导出。这里的选择不会修改已归档的会议、逐字稿或录音；会议正文请到会话浏览中编辑并保存。

当前稿、比较稿和采用前稿保留在本次界面中。开始新的录音或文件转写、清空文字会重置这组比较草稿；需要留存的内容请先复制或导出。没有手动改字时，文件识别文字仍按进度正常更新。

阅读逐字稿，跟随原声核对

在「会话浏览 → 逐字稿预览」，默认直接阅读每段正文。时间、说话人、整理文字和编辑放在同一行，短句不再占据大块输入框。此改进从 r492 提供。

  1. 点击「编辑」修改本段正文或说话人，再用「保存文本」或相应的改名按钮保存。「收起编辑」会保留草稿；「恢复」用于放弃本地修改。
  2. 点击段落时间，从这一段开始回听原声。可暂停、停止，或勾选「接续播放」听后续片段；原声缺失或暂不可读时，文字仍可阅读。
  3. 「跟随原声」按整段时间高亮。手动滚动、筛选或翻页会暂停跟随；编辑时不会自动抢走阅读位置。需要时重新勾选跟随。
  4. 开始录音或音频转写时，原声回听会停止。录音或逐字稿发生变化后，先刷新，再重新回听。

高亮按片段时间切换，不是逐字精确对齐。「接续播放」从下一片段的起点继续，不包含未选中的段间空隙。正在录音、尚未保存的内容不提供这种原声回听。原声留在本机，仅在点击播放后按需读取。

找回最近的语音输入结果

语音已识别，却没出现在目标输入框中时，回到主窗口，展开「最近输入结果」。这里保留本次打开软件期间接纳的最终识别段，只收录已开启「输入到当前窗口」的录音任务。无需重新识别；普通会议或文件转写请查看原始文本及会话浏览。

  1. 按时间选择片段，核对只读「识别稿」。启用了翻译时，「译文」另列主目标语言；未完成翻译时仍可复制识别稿。多语言的其他译文请到原有翻译区核对。
  2. 先查看原目标输入框，再点「复制识别稿」或「复制译文」，回到目标处手动粘贴。文字可能已经输入了一部分，粘贴前请避免重复。「已复制」只代表复制动作完成，不代表已输入成功。
  3. 有新结果时，不会切走您正在查看的片段。暂不可读取时可点「刷新」；复制失败仍可选中文字手动复制。
  4. 「清空本列表」只清空这里，不改原始转写、已保存会话或录音。若清空时刚收到新结果，会先保留并提醒您重新核对。

这是临时找回入口，最多 64 段，并有文字总容量限制。更早或超长内容未列出时会提示，请核对原始转写或已保存会话；需要长期留存的文字请主动保存或导出。关闭软件后本列表不会恢复。这里只读展示和按需复制，不会自动再次输入、重试录音或发送回车。

改正术语，确认后再记住

打开「原始文本 → 整理文字」或逐字稿中的「整理文字」，在原文副本里选中一个误识别的短词，再替换成正确写法，会出现「记住……？」建议。普通整段编辑不会自动学习；也可主动点「记住一个术语」填写词对。

  1. 核对「识别成」和「以后写成」。只填写两个不同的 1–24 字术语，可以含文字、数字及 _ . / -，不要填写整句、空白或纯数字修订。
  2. 来自项目逐字稿时默认仅本项目，详见下方项目词典。无项目归属时默认当前用途；中央用途规则会被不同项目共用，选择「中央 · 所有用途」时还需勾选确认。
  3. 点「确认记住」才保存。「取消」不保存；「忽略本次」不学习，并在本工作区本次打开期间抑制同一词对重复建议。输入法组合输入完成前不提出建议。
  4. 保存成功后可点「撤销刚记住的词」。只撤销刚添加的规则，不恢复旧稿或清空其他词条；中央设置后来有改变时，会保留并提示先核对词典。相同规则不重复添加。
  5. 规则不会立即改写当前稿，也不会打开自动输入。原文模式保留原样；在文字整理工作区主动选择保守规则或改口与格式，再点「整理文字」核对效果。禁改词、重叠规则、词典容量或未应用草稿有冲突时，先到「管理词典」处理。

保存和撤销传递所选词对、文字设置及必要的本机项目标识，不保存本段正文，不读取其他应用或剪贴板。中央用途规则跨项目复用；项目专属规则见下节。一次只保留最近一次新增规则的快捷撤销；其他规则可到管理词典移除。

项目专属词典，确认后仅在本项目整理时使用

先把已保存录音归入资料库中的项目，再从这条录音的逐字稿 → 整理文字打开工作区。「项目词典」显示实际归属项目和词条数量；它依据录音归属核对，名称相同也不会借用另一个项目的词。

  1. 选中误识别的短词并改正，或点「记住一个术语」。保存范围默认「仅……项目」。确认项目名称与词对后，再点「确认记住」。选择「中央 · 普通文字」等用途会跨项目共用；「中央 · 所有用途」还需另行勾选。
  2. 规则不会改动原始转写、录音或旧报告。主动选择本次「保守规则」或「改口与格式」，再点「整理文字」核对；原文模式仍严格保留原样。这是文字整理词典，不代表语音模型已经学会识别该词。
  3. 需要查看或移除时，展开「查看并管理本项目词条」。移除只影响这个项目；可用「恢复刚移除的词」恢复最近一次移除。刚添加的词仍可用下方的撤销按钮撤销。
  4. 移动条目、归档项目、修改词典或中央规则后，先刷新核对。旧项目的迟到结果不会替换当前稿；复制整理稿前也会重新核对项目。发现变化时，保留文字并要求重新整理。

尚未归入项目的录音会明确提示，并使用中央规则；独立原始文本不猜测所属项目。词典读取失败或项目归档时，不会静默改用另一个项目的规则。

每项目最多 64 条，合并后的有效规则也受容量上限约束。相同词对只处理一次；不同含义的中央规则、禁改词或重叠词条发生冲突时，需要先核对。当前从已归属项目的逐字稿进入；批量导入词典及空项目的独立管理入口尚未提供。

批量导入词典，查看和撤销变更

此词典入口需 Windows r512 或后续安装预览；Mac r492 源码 ZIP 尚未包含。

  1. 跨项目共用的词，在文字设置点「词典导入与历史」；仅项目使用的词，在资料库选中项目，点「项目词典与历史」。还没有录音的空项目也能提前准备。已有文字规则草稿时，先应用或放弃草稿。
  2. 粘贴词典，或明确选择 UTF-8 的 JSON、TSV、CSV 文件；选择对应格式，点「预览导入」。文件最多 256 条候选、64 KiB；保存的规则仍最多 64 条。
  3. 核对「新词」「已存在」「替换 · 需确认」「规则冲突」「格式无效」。替换项不会自动勾选，请先看原写法，再逐条确认。组合冲突或超过容量时减少选择，不会自动截断。点「确认采用所选词条」后才保存。
  4. 展开「变更历史」，核对日期和新增、移除的词。点「撤销这次变更…」，阅读提示后再次确认。后来新增的无关词保留；相关词已改动时先刷新核对，不直接覆盖。
  5. 如果写入结果无法确认，输入会保留。点「刷新词典与历史」查看实际保存结果，再决定下一步。保存中关闭面板不会取消已发出的写入，重新打开同一词典核对即可。

表格列名可用「听到、写成、用途」，也可用 from、to、scope。用途列可省略，默认 all；中央词典还可指定 plain、chat、email、list、code。项目词典的 all 只在该项目内生效。支持 CSV 引号内的逗号、UTF-8 BOM。
